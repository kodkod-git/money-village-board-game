# 온보딩 4개 화면 Figma 반응형 동기화 — 작업 프롬프트

> `20260907_figma_responsive_sync_proposal.md`에서 확정한 내용을 그대로 실행할 수 있게
> 요약한 버전. 다른 Claude Code 세션에 프롬프트로 그대로 붙여넣어 쓰면 된다.

```
[온보딩 4개 화면 Figma 반응형 동기화]

대상: LandingPage(홈) · NameInput(이름 입력) · TeamCodeInput(팀 참여) · CharacterSelect(캐릭터 선택)
— 이 4개 화면만. 다른 화면(로비/팀 현황/랭킹/퀴즈/관리자)은 건드리지 않는다.

1. 공통 인프라
   - 4개 화면에 useBodyClass('onboarding-mode') 적용 (quiz-mode/admin-mode와 같은 기존 패턴).
   - index.css에 body.onboarding-mode 전용 #root 규칙 추가.
   - 상한: 834×1194px(Figma 프레임 원본)를 절대 상한으로 — 화면이 그보다 커져도 프레임은 거기서
     성장을 멈춘다(카드처럼 가운데 뜬 채 유지).
   - #root에 container-type: size를 걸어서, 화면 CSS가 cqw(가로)/cqh(세로) 단위로 값을 계산할
     수 있게 한다.

2. 축소 규칙 — 통짜 스케일 금지, 축(가로/세로)을 나눠서 스케일
   - 가로 방향 값(좌우 여백, 버튼/카드 너비, 가로 gap) → 가로 폭 기준(cqw)으로 스케일.
   - 세로 방향 값(블록 사이 세로 gap, 위아래 패딩) → 세로 길이 기준(cqh)으로 스케일.
   - 정사각형이어야 하는 요소(아이콘, 캐릭터 카드)는 aspect-ratio: 1로 별도 고정.
   - 이렇게 축을 나누면 화면 비율이 Figma(834:1194)와 많이 다른 기기(세로로 긴 폰 등)에서도
     빈 여백이 남거나 잘리지 않는다. CharacterSelect.module.css의 그리드가 이미 이 방식을
     일부 쓰고 있으니(width: min(100cqw, 100cqh)) 그 패턴을 화면 전체로 확장하면 된다.

3. 값의 출처 — 절대 어림짐작하지 말 것
   - 모든 px 값은 Figma MCP(get_metadata / get_variable_defs / get_screenshot)로 직접 실측한
     값을 그대로 쓴다.
   - 화면마다 작업 전에 "가로 gap 표"와 "세로 gap 표"를 먼저 만들고, 그 값을 그대로 코드로 옮긴다.
     예시(캐릭터 선택 화면, 834×1194 기준):
       세로 gap: 뒤로가기→헤더 24px / 헤더→구분선 24px / 구분선→그리드 24px
     (지금 코드엔 이 세 값이 각각 96px/10px/44px로 서로 다르게 들어가 있어 어긋나 있었음 —
      전부 24px로 통일해서 옮길 것)

4. 하한 — 기존 값 유지
   - --app-min-height, --app-max-width 등 지금 index.css에 있는 최소 크기 값 그대로 사용.

5. 범위 제외
   - 홈 화면의 "우리 아이 경제 잠재력 테스트" 퀴즈 링크 버튼은 이번 작업에서 손대지 않는다.
   - 이름 입력(NameInput) 화면은 별도 Figma 프레임이 없으므로, 팀 참여(TeamCodeInput) 화면과
     같은 템플릿(라벨/문구만 다름)을 재사용한다.

작업 순서: 1번(공통 인프라) → 홈 → 팀 참여+이름 입력 → 캐릭터 선택 순으로, 화면마다 가로/세로
gap 표를 먼저 만들고 → 코드 반영 → 834×1194 및 축소된 임의 크기에서 Figma와 대조 확인.
```
