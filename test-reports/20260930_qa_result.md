## 4. 발견된 이슈

### ISSUE-B — 대시보드가 연결 끊김을 실시간으로 반영하지 않아 "전체 등록" 경고가 누락됨 (심각도: 중간)

| 항목 | 내용 |
|---|---|
| 역할 | 선생님 |
| 화면/기능 | 수업 대시보드 그리드 "연결 끊김" 배지 / "전체 등록" 확인 다이얼로그 |
| 재현 경로 | 대시보드를 열어둔 상태 → 등록 대기 팀의 학생 한 명 연결 끊김 → (새로고침 없이) "전체 등록" 클릭 |
| 기대 동작 | 그리드에 "연결 끊김" 배지, 다이얼로그에 경고 문구(스펙 1.2) |
| 실제 동작 | 배지 없음, 기본 문구 표시. 새로고침하면 정상. 재현 1/1 |
| 원인 | `server/index.js`의 `socket.on('disconnect')` 핸들러가 `room-updated`만 보내고 `broadcastClassRooms(room.classId)`를 호출하지 않음 → 대시보드의 `class-rooms-updated` 구독이 트리거되지 않음. (팀 모달은 자체 폴링이 있어 몇 초 뒤 배지가 뜨지만, 모달을 연 직후 폴링 전에 바로 "결과 등록"을 누르면 같은 이유로 기본 문구가 뜰 수 있음) |
| 영향 | 등록 자체는 정상 진행되고 데이터도 모두 저장됨. 관리자가 "일부 학생은 결과 화면이 안 뜬다"는 사전 경고를 못 받는 것이 문제 |
| 제안 | disconnect 핸들러(및 재접속 시)에 `broadcastClassRooms(room.classId)` 추가 |

### ISSUE-C — 등록 후 재접속한 학생이 빈 팀 화면에 갇힘 (심각도: 낮음~중간, UX)

| 항목 | 내용 |
|---|---|
| 역할 | 학생 |
| 화면/기능 | 팀 화면(`/team/:code`) 재접속 |
| 재현 경로 | 학생 연결 끊김 → 관리자가 경고 확인 후 결과 등록 → 학생이 다시 접속(같은 탭에서 팀 화면 복귀/새로고침) |
| 기대 동작 | "이미 결과가 등록되었어요" 같은 안내, 또는 해당 결과/랭킹 화면으로 이동 |
| 실제 동작 | 팀원 0명·"대기중" 4칸만 있는 빈 팀 화면, "자산 입력" 버튼도 없음. 콘솔 에러 없음 |
| 원인 | 서버 `join-room`은 방이 없으면 `callback({ ok:false, error:'Room not found' })`를 돌려주지만 `src/pages/Team.jsx`의 재접속 `socket.emit('join-room', …)`에 콜백이 없어 실패를 알 수 없음 |
| 비고 | 스펙상 "일부 참여자에게는 결과화면이 나오지 않을 수 있습니다"로 예고된 범위이긴 하나, 막다른 화면이 되는 것은 개선 여지가 있음. 결과는 랭킹 페이지에서는 확인 가능 |

### 관찰 사항 (이슈 아님)

- **연결 끊김 감지까지 15~40초 소요**: 탭을 다른 사이트로 이동시킨 경우 서버가 `connected:false`로 바꾸기까지 15~40초 걸렸다(Socket.IO ping timeout 범위). 9/18 세션의 "탭 닫기"는 약 3초였다. 수업 중엔 관리자가 끊김을 늦게 알아챌 수 있다는 정도로 참고.
- **그리드 카드 클릭 대상**: 팀 카드의 헤더(팀 이름·코드) 부분은 클릭해도 모달이 열리지 않고 아래 카드 본문만 열린다. 자동화 중 발견, 기존 동작.

## 5. 총평

9/28 요청("연결 끊김이어도 경고 후 등록, 예 클릭 시 끊긴 학생 제외하고 결과 화면으로 이동")은 **핵심 동작 모두 의도대로 작동**한다.

1. 개별 등록: 버튼 활성, 경고 문구 정확, 아니요/예 모두 정상, 연결된 학생은 즉시 결과 화면 이동, 끊긴 학생의 자산도 결과에 빠짐없이 저장. **정상.**
2. 전체 등록: 등록 동작은 정상이나, **대시보드를 열어둔 채 끊김이 생기면 경고 문구가 안 뜨는 갱신 누락(ISSUE-B)** 이 있다. 새로고침하면 정상.
3. 재접속: 등록 전 재접속은 완벽히 복구(중복 없음, 경고 해제). **등록 후 재접속은 빈 화면에 머무는 UX 문제(ISSUE-C)**.
4. 직접 등록하기: 7단계 입력·취소·이전 단계 이동·저장·랭킹 반영 모두 정상.

ISSUE-B는 서버 한 줄(`broadcastClassRooms`) 수정으로 해결 가능하므로 우선 조치를 권장한다.
