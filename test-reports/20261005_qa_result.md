### 진행 방식 / 테스터 제약

- 관리자 로그인은 운영 서버라 사용자가 직접 로그인했고, 이후 조작은 그 세션으로 진행했다.
- 학생 20명은 탭마다 별도 sessionStorage(= 별도 기기)로 동작한다. 각 탭에 같은 조작 스크립트(이름 입력 → 캐릭터 선택 → 로비 → 방 만들기/합류 → 자산 입력 5단계)를 주입하고, **20개 탭에서 동시에 시작**시켜 실제 동시 접속·동시 입력 상황을 재현했다. 모든 클릭은 실제 화면 버튼(DOM)으로 했고 관리자 API 단축은 쓰지 않았다.
- 백그라운드 탭은 Chrome 타이머 제한(throttling)을 받아, 첫 입장 때 일부 학생이 조작 스크립트의 대기 시간(20초) 안에 팀 카드를 못 찾았다. 앱 문제가 아니라 자동화 조건 때문이라 같은 탭에서 다시 실행해 합류시켰다(아래 3.1 참고). 이후 스크립트의 대기 방식을 바꿔 자산 입력·등록 단계는 한 번에 끝났다.
- 연결 끊김 시나리오(9/18·9/30에 검증)는 이번 요청 범위가 아니라 다시 하지 않았다.

### 관찰 사항 (결함 아님 / 참고)

- **가격 입력 키패드는 기존 값 뒤에 숫자를 이어 붙인다**: 가격 2,000에서 "3500"을 누르면 `20003500` → 최대값 1,000,000으로 잘림. 학생 기기에서는 ← 로 지우고 입력해야 한다. 의도된 동작일 수 있으나 처음 쓰는 사람은 헷갈릴 수 있음.
- **같은 금액은 서로 다른 순위**: 관리자 랭킹에서 25,500원 3명이 11·12·13위로 표시된다(공동 순위 아님).
- **결과 화면 링크 복사 시 안내 없음**: 커밋 `934cc18`에서 의도적으로 없앤 것으로 확인.
- **관리자 대시보드 반영 지연**: 개별 등록 직후 대시보드 카운트가 몇 초 늦게 바뀐 경우가 있었다(관리자 탭이 백그라운드여서 생긴 지연일 가능성이 큼). 데이터는 정상 저장됨.
- **서버 부하 참고**: `GET /api/admin/rooms`가 폴링 때마다 `game_sessions`, `game_results` **전체 테이블**을 읽은 뒤 수업별로 거른다. 21명 규모에선 문제없지만, 누적 데이터가 커지거나 여러 반이 동시에 수업하면 응답이 느려질 수 있다.
- 결과 화면 "전체" 탭에는 과거 QA 데이터(예: "QA1 3,602,040,000원")가 섞여 1위로 노출된다. 실제 수업 전에 테스트 데이터를 지우는 것을 권장.

## 6. 총평

1. **5팀(20명) 동시 진행 — 정상.** 20명이 동시에 입장·팀 구성·자산 입력을 해도 데이터가 섞이거나 빠지지 않았다. 20명의 저장값이 입력값과 모두 일치했고, 개별 등록과 전체 등록 모두 해당 팀 학생만 각자 결과 화면으로 정확히 이동했다.
2. **실시간 동기화 — 정상.** 팀 화면, 관리자 그리드·모달, 다른 학생의 로비 화면까지 참가·완료·등록 상태가 새로고침 없이 반영됐다.
3. **만족도 조사(신규) — 정상.** 관리자 QR 2곳(수업 목록·팀 현황)과 학생 결과 화면 링크 모두 같은 구글 폼으로 연결되고, 새 탭으로 열린다.
4. **개선 권장:** ISSUE-2(등록 후 "팀 N" 번호가 바뀜)는 실제 수업에서 선생님이 헷갈릴 수 있어 우선 조치를 권장한다. ISSUE-1·3은 문구/표시 개선 수준이다.
