# DB 설계 스펙: Supabase 결과 저장

**날짜:** 2026-06-18  
**목표:** "결과 등록하기" 버튼 클릭 시 게임 결과를 Supabase에 영구 저장하고, 팀 내 결과 화면을 표시한다.

---

## 배경

현재 모든 게임 데이터(방, 플레이어, 가격, 게임 상태)는 서버 in-memory에만 존재한다. 서버 재시작 또는 플레이어 연결 종료 시 데이터가 사라진다. 이번 작업은 게임 종료 시점에 결과를 Supabase에 저장하고, 결과 화면(`/result/:sessionId`)에서 조회하는 것을 목표로 한다.

---

## 범위

- **현재 구현:** 게임 결과 저장 + 팀 내 4인 순위 결과 화면
- **추후 확장:** 팀 간 리더보드/통계 (테이블 구조 변경 없이 쿼리 추가로 가능)

---

## 테이블 구조

### `game_sessions`

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | UUID PK | `gen_random_uuid()` |
| `team_code` | TEXT UNIQUE NOT NULL | 6자리 팀 코드 (예: `ABC123`) |
| `stock_prices` | JSONB NOT NULL | `{"semiconductor":2000, "finance":4000, ...}` |
| `real_estate_prices` | JSONB NOT NULL | `{"gaon":10000, "nuri":20000, ...}` |
| `created_at` | TIMESTAMPTZ | `now()` |

### `game_results`

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | UUID PK | `gen_random_uuid()` |
| `session_id` | UUID FK → game_sessions(id) | |
| `player_uuid` | UUID NOT NULL | 클라이언트 localStorage에서 생성·보관 |
| `name` | TEXT NOT NULL | 플레이어 입력 이름 |
| `character` | TEXT NOT NULL | 선택한 캐릭터 |
| `job` | TEXT NOT NULL | 직업 코드 (`'a'`~`'f'`) |
| `cash` | INTEGER NOT NULL | 현금 (원 단위) |
| `stock_holdings` | JSONB NOT NULL | `{"semiconductor":3, "finance":1, ...}` |
| `real_estate_holdings` | JSONB NOT NULL | `{"gaon":2, "chorong":0, ...}` |
| `badges` | JSONB NOT NULL | `[true, false, true, false, true, false]` |
| `total_assets` | NUMERIC NOT NULL | 서버에서 계산 후 저장 |
| `created_at` | TIMESTAMPTZ | `now()` |

---

## total_assets 계산식

```
badge_count  = badges 배열에서 true인 개수 (0~6)
base_assets  = cash
             + Σ (stock_holdings[key] × stock_prices[key])
             + Σ (real_estate_holdings[key] × real_estate_prices[key])

total_assets = base_assets × (badge_count × 0.5)
```

| 뱃지 수 | 배율 |
|---|---|
| 0개 | ×0.0 (= 0원) |
| 1개 | ×0.5 |
| 2개 | ×1.0 |
| 3개 | ×1.5 |
| 4개 | ×2.0 |
| 5개 | ×2.5 |
| 6개 | ×3.0 |

> NUMERIC 타입 사용 이유: 뱃지가 홀수 개일 때 base_assets × 0.5가 소수점을 가질 수 있음.

---

## 유저 식별: 익명 UUID

- 플레이어가 처음 앱을 열 때 `crypto.randomUUID()`로 UUID 생성
- `localStorage`에 `player_uuid` 키로 저장 (브라우저 재방문 시 재사용)
- `join-room` 소켓 이벤트에 `playerUuid` 필드 추가하여 서버로 전송
- 서버는 player 객체에 `playerUuid`를 포함해 관리

## 데이터 흐름

```
[Host Client]
  1. 모든 플레이어 isCompleted === true
  2. "결과 등록하기" 버튼 활성화 → 클릭
  3. POST /api/rooms/:code/submit 요청

[Server]
  4. in-memory room 조회 (players + prices)
  5. 각 플레이어 total_assets 계산
  6. Supabase: game_sessions INSERT
  7. Supabase: game_results INSERT × 4
  8. { sessionId } 반환

[Host Client]
  9. /result/:sessionId 로 이동

[Result Page]
  10. GET /api/results/:sessionId 요청
  11. Supabase에서 조회 후 total_assets DESC 정렬
  12. 순위표 표시
```

---

## API

### `POST /api/rooms/:code/submit`

결과를 Supabase에 저장하고 session ID를 반환한다.

**응답:**
```json
{ "sessionId": "uuid" }
```

**에러:**
- `404` — room not found
- `400` — 아직 모든 플레이어가 완료하지 않은 경우
- `409` — 이미 제출된 경우 (team_code UNIQUE 제약으로 중복 방지)

### `GET /api/results/:sessionId`

결과 페이지에서 순위를 조회한다.

**응답:**
```json
{
  "teamCode": "ABC123",
  "createdAt": "2026-06-18T...",
  "stockPrices": { "semiconductor": 2000, ... },
  "realEstatePrices": { "gaon": 10000, ... },
  "players": [
    {
      "rank": 1,
      "name": "홍길동",
      "character": "fox",
      "job": "a",
      "cash": 50000,
      "stockHoldings": { "semiconductor": 3, ... },
      "realEstateHoldings": { "gaon": 2, ... },
      "badges": [true, false, true, false, true, false],
      "totalAssets": 3200000
    }
  ]
}
```

---

## 결과 페이지 (`/result/:sessionId`)

- 팀 코드 + 게임 날짜 표시
- 4명 순위표 (total_assets DESC 정렬)
- 각 플레이어 카드 탭 시 상세 내역 (현금 / 주식 / 부동산 / 뱃지) 확인
- **로그인 없이 URL 공유**로 접근 가능
- Supabase Row Level Security: `game_sessions`, `game_results` 읽기 공개

---

## Supabase 설정

- **프로젝트:** 신규 생성
- **RLS 정책:**
  - `game_sessions`: SELECT 공개, INSERT 서버(service role key)만
  - `game_results`: SELECT 공개, INSERT 서버(service role key)만
- **환경 변수 (서버):**
  - `SUPABASE_URL`
  - `SUPABASE_SERVICE_ROLE_KEY`

---

## 추후 리더보드 확장 방안

테이블 구조 변경 없이 아래로 대응 가능:

- **팀 간 순위:** `SELECT * FROM game_results ORDER BY total_assets DESC`
- **종목별 통계:** `stock_holdings->>'semiconductor'` JSONB 쿼리
- **BI 툴 연동:** DB View로 JSONB 컬럼을 일반 컬럼으로 펼쳐서 노출

## 결정 사항 요약

| 항목 | 결정 |
|---|---|
| DB | Supabase (PostgreSQL) |
| 스키마 방식 | 하이브리드 (prices/holdings는 JSONB, total_assets는 컬럼) |
| 유저 식별 | 익명 UUID (localStorage) |
| 팀코드 재사용 | 불가 (UNIQUE 제약, 1코드 = 1세션) |
| 결과 조회 권한 | URL 공개 (RLS 읽기 허용) |
| 현재 범위 | 팀 내 4인 순위 결과 화면 |
| 추후 범위 | 팀 간 리더보드 (구조 변경 없이 확장) |
