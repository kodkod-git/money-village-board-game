# 관리자 모드 모바일 대응 설계

- 작성일: 2026-11-05
- 요청 문서: `proposal/20261105_admin_mobile.md`

이 문서는 요청 문서를 바탕으로 코드를 확인해 구체화한 설계다. 기능별 지원 범위(요청 문서 1장)와 범위 밖 항목(5장)은 그대로 따른다.

## 목표

관리자 모드(`/admin`)를 휴대폰에서 쓸 수 있게 한다. 모바일 전용 화면을 따로 만들지 않고 지금 화면을 반응형으로 바꾼다. **768px 이상의 모습과 동작은 바뀌지 않아야 한다.**

## 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 화면 폭 기준 | 모바일 767px 이하, PC·태블릿 768px 이상 | 플레이어 화면의 `min-width: 768px`와 맞춘다 |
| 시트 구현 | 각 창의 CSS에 모바일 규칙을 추가한다. 공용 시트 컴포넌트는 만들지 않는다 | 창의 구조를 바꾸지 않아 PC 영향이 거의 없다 |
| 관전에서 연 학생 정보 | 전체 화면으로 보여 준다 | 시트가 겹치지 않고 항목 5개를 넓게 볼 수 있다 |
| 랭킹에서 연 학생 정보(읽기 전용) | 시트로 보여 준다 | 그 위에 다른 시트가 뜨지 않는다 |
| 현금 수정 | `수정`을 누르면 바로 숫자 키패드를 연다 | 한 번에 입력할 수 있고 창이 겹치지 않는다. 한글 금액 표시는 모바일에서 보이지 않는다 |
| 수정 창 버튼 | 지금 있는 `확인`을 하단에 고정한다 | 요청 문서의 저장·취소 버튼은 코드에 없다. 닫기는 지금의 `✕`와 바깥 영역 누르기를 유지한다 |

## 공통 부품

### `useIsAdminMobile` (`src/hooks/useIsAdminMobile.js`)

- `window.matchMedia('(max-width: 767px)')`로 판단하고 `change` 이벤트로 값을 갱신한다.
- `matchMedia`가 없는 환경(테스트 환경)에서는 `false`(PC)를 돌려준다. 기존 테스트가 PC 동작을 그대로 검증하게 하기 위해서다.
- 보여 주는 컴포넌트나 동작이 달라질 때만 쓴다. 스타일만 다르면 각 CSS의 `@media (max-width: 767px)`로 처리한다.
- 기준값은 `src/index.css`의 관리자 변수 블록 주석에 적어 둔다.

### `AdminBottomNav` (`src/components/admin/AdminBottomNav.jsx`)

- 수업 목록, 팀 현황, 랭킹 보기, 설정 탭을 아이콘과 이름으로 항상 함께 보여 준다.
- 수업을 선택하기 전에는 팀 현황과 랭킹 보기를 비활성화한다(사이드바와 같은 규칙).
- `NAV_ITEMS`는 사이드바에서 별도 파일(`src/components/admin/adminNavItems.js`)로 옮겨 함께 쓴다. 분석 메뉴 두 개에 `mobile: false`를 붙여 탭바에서 거른다.
- 터치 영역은 44px 이상이고, 높이에 `env(safe-area-inset-bottom)`을 더한다.

### `AdminOverflowMenu` (`src/components/admin/AdminOverflowMenu.jsx`)

- `⋯` 버튼을 누르면 열리는 메뉴다. 수업 목록, 팀 현황, 관전에서 함께 쓴다.
- 입력: `label`, `items`(`{ key, label, onSelect, danger, disabled }` 목록). `danger` 항목은 빨간 글씨로 맨 아래에 구분해 둔다.
- 메뉴 바깥을 누르거나 Esc를 누르면 닫힌다. 항목을 고르면 닫힌 뒤 `onSelect`를 부른다.
- 되돌릴 수 없는 작업은 메뉴를 고른 뒤 지금처럼 `ConfirmDialog`(tone="danger")를 거친다.

## 화면 틀

- `AdminShell`: 모바일이면 사이드바 대신 본문 아래에 `AdminBottomNav`를 둔다. `.shell`을 세로 배치로 바꿔 탭바가 본문을 가리지 않게 한다.
- `AdminDashboard`: 모바일에서 `responses`, `all-results` 구역이면 해당 화면 대신 가운데에 "PC에서 이용해 주세요" 문구를 보여 준다. `section` 상태는 그대로 두므로 다시 넓히면 원래 화면이 나오고, 탭바로 다른 메뉴로 갈 수 있다.
- 모바일에서는 의도한 영역(랭킹 분류 탭)을 빼고 가로 스크롤이 생기지 않아야 한다.

## 화면별 동작

### 수업 목록 (`AdminClassList`)

- 헤더의 이름과 로그아웃은 숨긴다. 설정 탭에 같은 기능이 있다.
- 입력창과 `수업 생성하기` 버튼을 세로로 쌓고 가로를 채운다.
- 행을 누르면 수업으로 들어간다. 만족도 조사·QR·삭제는 `⋯` 메뉴로 옮긴다.
- `unassigned` 수업은 지금도 이 버튼들이 없으므로 `⋯`도 표시하지 않는다.

### 팀 현황 (`AdminClassDashboard`)

- 순서: 수업 이름과 `⋯`(QR 코드, 만족도 조사, 전체 삭제) → 검색창 → `전체 등록` → 통계 카드 2×2 → 팀 카드 한 줄 1개 → `방 만들기` 카드.
- 설명 문구와 보기 전환 탭은 숨긴다.
- 보여 줄 탭은 `const visibleTab = isMobile ? 'grid' : activeTab`으로 계산한다. `activeTab` 상태를 바꾸지 않으므로 다시 넓히면 보던 탭으로 돌아온다. 결과 불러오기도 `visibleTab`을 기준으로 한다.
- 수업 이름과 `⋯`, 카드 안 탭 등 누르는 요소는 44px 이상으로 한다.
- 표·유형 분포·팀 대결 화면은 수정하지 않는다.

### 관전 (`AdminSpectateModal`)

- 모바일에서는 팝업이 화면 전체를 덮는다(`100dvh`, 모서리 없음). 학생 카드는 지금처럼 2×2로 둔다.
- **넘기기:** 손가락을 뗄 때 가로 이동이 50px 이상이고 세로 이동보다 크면 팀을 바꾼다. 첫 팀과 마지막 팀에서는 더 넘어가지 않는다.
- **넘기기를 끄는 때:** 모바일이 아닐 때, 학생 정보 화면이나 다른 창이 열려 있을 때, 터치가 입력칸에서 시작됐을 때.
- 이전/다음 버튼은 그대로 둔다.
- 하단 주요 버튼은 `가격 설정`, `결과 등록`이고 각각 지금과 같은 조건에서만 보인다. 그 밖의 항목은 `⋯` 메뉴로 옮긴다.
  - 카카오 공유, 링크 복사: `canShare`일 때
  - 자세히 보기: 항상
  - 직접 등록하기: 지금과 같은 조건일 때
  - 삭제: 항상, 맨 아래 빨간색
- 공유 결과 안내(`shareNotice`)는 지금처럼 하단에 보여 준다.

### 수정 창

| 대상 | 모바일 동작 |
|---|---|
| `AdminEditModal` (관전) | 전체 화면. 두 단을 한 단으로 쌓는다 |
| `AdminEditModal` (랭킹, `readOnly`) | 시트 |
| 직업, 성공열쇠, 주식, 부동산 수정 | 시트. `FieldEditModal.module.css` 한 곳에서 처리한다 |
| 현금 수정 | `NumberInputModal`을 바로 연다 (`maxValue`는 `MAX_CASH`) |
| `AdminPriceSettingModal`, `AdminTeamAssetsModal`, `AdminAddPlayerModal` | 시트 |
| `ConfirmDialog`, `ClassQRModal`, `SurveyQRModal` | 가운데 팝업 유지, 폭은 `calc(100vw - 32px)` 이하 |

- 시트 공통: 가로를 채우고 위쪽 모서리만 둥글며 최대 높이는 `90dvh`다. 내용은 안에서 스크롤하고 `확인`은 하단에 고정하며 `env(safe-area-inset-bottom)`을 더한다.
- `AssetQtyStepper`: 모바일에서 `+`, `-`는 44px 이상이다. 가운데 숫자를 누르면 입력칸 대신 `NumberInputModal`을 연다(`maxValue`는 `max`). 종목이 여러 개라 시트를 없앨 수 없으므로, 수량 키패드는 시트 위에 겹치는 예외로 둔다.
- PC에서는 현금 입력창과 수량 입력칸이 지금 그대로다.

### 랭킹 (`AdminRankingView`)

- 모바일 순서: 제목과 수업 이름 → 분류 탭(넘치면 가로 스크롤) → 검색창 → 시상대 → 순위 목록. `★ 관리자 모드` 배지는 숨긴다.
- 시상대는 `RankingPodium`을 쓰고 1~3위가 모두 있을 때만 보여 준다. 검색어가 있으면 숨긴다.
- 순위 목록은 `RankingTable`을 쓴다. 1~3위도 목록에 다시 나온다(플레이어 화면과 같다).
- `RankingTable`에 `getSub` prop을 추가한다. 없으면 지금처럼 `row.className`을 보여 주고, 관리자 랭킹은 `row.teamName || row.teamCode`를 넘긴다.
- 줄이나 시상대를 누르면 `AdminEditModal`(`readOnly`)을 시트로 띄운다.
- 값 키는 관리자 화면의 `VALUE_KEYS`를 그대로 쓴다. PC의 시상대와 표는 수정하지 않는다.

### 설정 (`AdminSettings`)

- 한 단으로 쌓고 로그아웃 버튼은 가로를 채운다.

## 서버와 오류 처리

서버와 API는 바꾸지 않는다. 저장 실패 같은 오류 처리도 지금 동작을 따른다.

## 테스트

자동 테스트(vitest)로 다음을 확인한다. 모바일 환경은 `matchMedia` 모의 함수로 만든다.

- `useIsAdminMobile`: 767px과 768px 판단, 폭 변경 시 갱신, `matchMedia`가 없을 때 `false`
- `AdminBottomNav`: 탭 4개만 표시, 수업 미선택 시 비활성화
- `AdminDashboard`: 모바일에서 분석 구역이면 안내 문구 표시
- `AdminClassDashboard`: 모바일에서 보기 탭 숨김, 표 탭을 보다가 좁히면 그리드, 다시 넓히면 표
- `AdminOverflowMenu`: 항목 선택, 닫기, 위험 항목 위치
- `AdminClassList`, `AdminSpectateModal`: 삭제가 메뉴와 확인 창을 거침
- `AdminSpectateModal` 넘기기: 가로로 밀면 변경, 세로로 밀거나 끝 팀이거나 창이 열려 있으면 변경 없음
- `RankingTable`: `getSub` 있을 때와 없을 때
- `AdminRankingView`: 모바일에서 팀 이름 표시, 검색 중 시상대 숨김
- `CashEditModal`, `AssetQtyStepper`: 모바일은 키패드, PC는 지금 입력칸

단계마다 `npm test`가 통과해야 한다.

## 화면 확인

- 크기: 390×844, 360×800, 768×1024, 1280×800, 1440×900
- 대상: 수업 목록, 팀 현황(그리드), 관전, 수정 시트, 랭킹, 설정
- **PC 비교:** 구현을 시작하기 전에 768, 1280, 1440 폭 화면을 찍어 두고, 끝난 뒤 같은 임시 데이터로 다시 찍어 비교한다.
- **모바일 확인:** 가로 스크롤 없음, 잘린 버튼 없음, 탭바가 내용을 가리지 않음, 제외 메뉴와 탭이 보이지 않음, 분석 화면을 보다 좁히면 안내 문구가 나옴.
- API 응답은 임시 데이터로 대신한다. 실제 수업 데이터, 기기의 안전 영역, 스와이프 느낌은 이 방법으로 확인할 수 없으므로 실제 휴대폰에서 사용자가 확인한다.

## 작업 순서

1. PC 기준 스크린샷 촬영
2. 공통 준비: 훅, 기준값 주석, `NAV_ITEMS` 분리, `AdminOverflowMenu`
3. 화면 틀: `AdminShell`, `AdminBottomNav`, 분석 화면 안내 문구
4. 팀 현황과 관전
5. 수정 창과 키패드
6. 수업 목록, 랭킹, 설정
7. 스크린샷 확인과 PC 비교
